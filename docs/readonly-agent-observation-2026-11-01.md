## 可复核的缺陷与改进顺序

### P1：裁剪结果使模型反复请求已经读过的材料

原配置运行的 10 次模型请求，`role=tool` 的消息数量全部为零。首轮确实执行了三次读取，但下一轮的整个 assistant/tool 调用组已被 `fit_native_context` 删除。工作状态保留目录和计划，未保留未带查询词的普通读取内容。

第二轮重复读取同三个文件；第三轮将 `query` 改成空字符串，又读取了相同的文件开头。总共出现四次工具缓存复用，但结果仍无法进入下一次模型上下文。`None` 和空字符串还形成了不同的缓存键。

建议：为当前问题的关键摘录保留独立预算，普通读取也可留下带来源、字节范围和哈希的工作记忆；压缩工具结果时保留可用的结构化内容和调用闭合，记录裁剪原因。对等价的空查询规范化后再计算缓存身份。不能只依靠缩小原文或不断增大窗口。

代码：`workflows/native_context.py:204`、`workflows/native_mcp.py:_read_collected_evidence`。

### P1：最终报告没有独立的预算保障

配置对照保留了工具历史，但 Agent 连续顺序翻页，累计输入增至 131,921 Token。第八轮准备进入收尾时，已经记账的 Token 总量为 134,295，250,000 限额仍余 115,705；该轮按 UTF-8 字节数保守申请 122,452 Token，因此模型请求没有发出。

因此准确现象是“下一轮保守预留失败”，不是“实际 Token 全部用完”。报告轮次数虽有预留，报告所需的 Token/上下文空间却没有单独保障。

建议：把取证预算与报告预算分开；接近限额时只保留计划、关键摘录和缺口，使用小型报告上下文结束。按已观测的供应商用量校准估算，但保留预算上界约束。显示实际、已预留和可用额度，避免一个数字混用。

代码：`workflows/native_model.py:75`、`workflows/native_mcp.py:run`。

### P1：失败被呈现成完成，且建议指错方向

鉴权失败、两轮协议拒绝、输出截断和预算预留失败，最终都得到 `status=completed / resolution=inconclusive`，报告默认说“调查已完成受控执行并取得证据”，并建议补充真实证据。

本题已有 184,161 字节原始证据，阻碍是执行协议、上下文和预算。兜底报告的三条 Claim 也都只是 `evidence_metadata`，没有形成对问题的回答。外层 `investigation.run` span 仍是 `status=ok`；函数正常返回不能直接作为调查成功率。

建议：明确区分调查执行错误、依赖不可用、预算停止和证据不足。状态与摘要直接告诉用户失败发生在哪一层；保留可恢复检查点，建议修复模型接入或执行配置。追踪增加业务结果与停止原因，不只看 Python 异常是否抛出。

代码：`workflows/native_reporting.py:84`、`reports/builder.py:132`、`observability/tracing.py`。

### P2：模型配置与响应结束原因缺少供应商适配

原配置有三轮响应 2,048 个输出 Token 全部用于 reasoning，未产出可执行调用或最终 JSON，却被统一归为 `MODEL_INVALID_RESPONSE`。另一轮 `finish_reason=length` 返回了部分工具调用，其中两次搜索执行、一次不完整参数报错。核心归一化没有保留结束原因，无法区分截断、协议错误和服务不可用。

建议：采用供应商配置档，声明窗口、输出上限、Thinking 协议、扩展字段及用量结构。区分 `length`、拒绝、格式错误和鉴权错误，采取有界恢复动作。Thinking 模式的多轮工具协议也需要专门适配，不能只换密钥和模型名。`index` 的执行信封兼容已修复，其余仍是待办。

DeepSeek 文档明确说明 Thinking 默认启用，并对工具会话规定了单独的上下文回传要求；对照通过显式关闭模式避免依赖这条尚未适配的路径。[官方说明](https://api-docs.deepseek.com/guides/thinking_mode/)

### P2：读取策略、计划推进和停滞判断需要配合

配置对照请求中的工具消息从 4 条增长到 14 条，说明原文保留问题确实得到缓解；但模型连续顺序翻页，没有调用跨证据检索。唯一一次计划更新为初始计划，结束时仍为一个进行中步骤和四个待办步骤。

停滞守卫在第六轮要求重新规划，第七轮要求结束；随后报告预算申请失败。更多读取与真实问题进展没有良好对应。

建议：对大 JSON 优先提供字段路径/有界片段检索，优先查断言、注入回执和恢复字段；要求取得能回答步骤的证据后更新该步骤，而非仅在提示中要求。停滞守卫应说明缺少哪项进展，并保证降级到可发布的有限报告，不让“重新规划”与“没有报告预算”互相抵消。
