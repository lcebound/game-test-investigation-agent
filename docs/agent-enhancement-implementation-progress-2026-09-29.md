## 第二步：受控候选选择（已接入）

- 设置调查约束 `enable_experiment_selection: true` 后，仅在存在至少两个活跃假设或明确缺失证据时启动候选比较。原模型决策与从现有证据生成的只读候选合计最多三个；没有适用候选时沿用原决策。
- 候选记录包含问题、能力版本、参数、可比字段、结构化预测、证据要求、分项预计成本和停止条件。程序检查真实能力、JSON Schema 参数、构建及环境信息、工具读取次数、真实 Run 数和设备分钟预算。实验还要求能力目录明确声明 `controllable_variables`，且目标选择器与环境指纹一致；缺少成本或可比控制时被过滤。
- 排序先看证据缺口与可执行预测区分的假设对数；价值相同时分别比较 Run 数、设备分钟和工具读取次数。自然语言描述不同不计入判别覆盖率。入选与未入选原因写入 `candidate.selection` 事件。
- 已注册 CSV 配方返回数值后，程序按可观测键和单位对照预测，记录 `supports`、`weakens` 或 `unknown`；支持或削弱只更新假设账本，不把一次观测升级成根因确认。结果与来源保存在 `candidate.outcome` 事件。
- 新增独立的 `CandidateDesign` 模型调用。只有同时设置 `enable_experiment_selection: true` 和 `enable_model_candidate_design: true` 且存在活跃假设与选择需求时才调用；每轮最多一次，失败记录原因并沿用原有候选。模型最多提出三个草案，选择器仍把最终候选限制为三个，并核对当前假设、预测所属操作、能力、参数、成本及预算。调用耗时和 Token 用量写入 `candidate.design` 事件。
- 真实 Run 的结构化 verdict 或执行状态现在也能与入选实验的预测对照。更新前核对决策、计划动作、Run 快照、已摄入的同动作证据、真实执行来源、构建、环境和参数。缺失观测或条件不可比时结果为 `unknown`，不会把空 verdict 当作反证。
- CSV 数值预测新增 `absolute_tolerance` 和至少 3 个样本的要求。对 `csv_summary_v1` 的中位数、P95、最小值或最大值作阈值判断时，验证样本数、单位、有限数值与最小/最大范围；整个范围在阈值同侧才给出支持或削弱，跨越阈值时保留 `unknown`。排序中的判别对数也考虑容差区间是否重叠。
- 可选约束 `min_comparable_runs: 2` 或 `3` 要求多个独立真实 Run 一致后才更新假设，且不得超过真实 Run 预算。只聚合同能力及版本、提供方、测试引用、参数、目标、执行约束、构建、环境和预测的记录；每条 Run 仍须有同动作同修订的当前可信证据。重复结果冲突时记录双方证据，并将此前的支持状态退回 `unresolved`。超过最近 500 条事件时也能分页找回较早观测。
- 最近三条候选结果会进入下一轮 `working_state.recent_candidate_outcomes`，让调查模型看见“可比运行次数不足”或“重复结果冲突”的原因；该摘要按事件类型读取，不会被其他高频事件挤出最近 500 条窗口。
- 来自真实 Run 的 CSV 经过 `csv_summary_v1` 分析后，可按 `derived_from` 回溯到原始 Run 证据、计划动作和已摄入的 Run 快照。程序还核对注册配方完成事件里的决策、输入/输出 ID 与 SHA-256。同一指标源、能力版本、参数、目标、构建和环境下的独立摘要会执行逐 Run 数值对照；不足次数、样本区间跨阈值、来源更换或结果冲突时均不增加支持结论。伪造的分析证据缺少匹配的配方事件会被拒绝。
- 指标源默认使用提供方的 `source_evidence_id` 精确对齐；若该 ID 每次 Run 不同，调查约束可显式提供 `metric_source_selector`，必须精确指定 `kind`、`mime_type`、`producer`、`producer_version`。同一次 Run 有多个匹配源时拒绝聚合，防止任意挑选较有利的一份。
- 本地 controller 和 Temporal activity 均接入同一选择器与结果更新服务。用性能 CSV 和功能日志两个问题族验证了“已有证据足够时先查/算”，以及无效参数、缺少可比条件被拒绝。
- 开关开启时的本地 controller 和 Temporal activity 集成用例已覆盖模型草案接入。测试还覆盖模型失败缓存、候选数量上限、虚构参数与错配预测拒绝，以及真实 Run 结果对照的幂等和环境不匹配。
- 新契约已导出为 v2 JSON Schema；既有 v1 快照保持原样。

候选设计与选择开关默认关闭；`min_comparable_runs` 默认 1。跨 Run 规则支持结构化 verdict、执行状态和注册 CSV 摘要的保守阈值对照。当前没有置信区间或分布估计，也没有真实 Qwen 与平台联调或完整分支评测。

## 第三步：离线分支驱动器（第一增量，2026-09-30）

- 新增 `evals/branching.py`，按策略返回的操作推进显式分支。每个节点必须覆盖目录中所有操作；未建模参数、能力不可用、越界引用和预算耗尽返回明确状态，均不提供成功观测。
- 策略只接收公共 `BranchView`，私有转移表、支持结论及评分标签不进入回调。回调使用深拷贝，避免修改预算或公开对象影响环境；这是可信代码的数据隔离接口，尚非进程沙箱。
- 同一场景用新建策略实例成对运行，仅切换候选选择开关。保存逐步决策、生产选择器记录、响应、终止、质量与模拟成本，并按集合提供开启减关闭的差值。缺少支持或所需引用的确定结论计入错误论断。
- 冻结清单核对场景、全部包内 Python 源码与运行时版本。源码 ZIP 保存本次可重现快照，避免后续只剩哈希而丢失源码；清单和结果不覆盖既有文件。
- 独立源码快照重放验证中发现 `python -m` 的模块类身份问题，已修复并增加子进程命令测试。修订版 `v2` 已在独立临时目录从 ZIP 重跑八条轨迹，全部通过，清单哈希、集合指标与成对差值均与归档结果一致。
- 四个 train 示例接入真实 `CandidateSelectionService.choose()`：性能补证选 CSV 分析，日志补证选读取，证据足够时结束，缺少构建时保留未解决。两种变体的脚本标签质量均为 100%；平均模拟运行数从 0.5 到 0，工具次数从 0 到 0.5。该结果仅验证接线，不构成独立模型能力或真实平台收益证据。
- 专项测试覆盖不同参数不同分支、隐藏标签不进入输入、回调修改隔离、未建模/越界/预算拒绝、合法补充信息、错误论断、场景/源码/运行时漂移拒绝、集合泄漏和源码快照哈希。

协议与冻结结果入口见 [离线分支评测](branch-evaluation.md)。当前公开上下文仍是初始元数据加环境观测，没有完整生产账本更新与 controller 重放。
