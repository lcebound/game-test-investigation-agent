# 调查可靠性与时间预算修复（2026-10-15）

新调查默认时间预算为 7200 秒（2 小时），默认累计设备预算为 120 分钟。工作台以分钟填写总时限；服务端默认值同时应用于前端、未完整指定预算的 API 请求以及平台事件自动创建的调查。显式请求预算优先，历史调查不修改，重启不延长原截止时间。

本次修复：

- 本机 API 启动后恢复未结束调查；优先查询已有运行，提交中断时按动作 ID 查找，复用原幂等键。已保存结果继续摄取证据，待输入任务保持等待。原 Provider 配置缺失时报告能力缺口并保留清理项。
- 状态轮询按剩余总时间与读取预算安排间隔，默认保留 8 次读取用于证据；本机事件可提前唤醒。Temporal 新工作流采用同一安排，并用 patch 标记保留已有工作流历史兼容性。资源租约覆盖调查时间预算。
- 失败日志在权限与预算允许时自动读取首段，进入后续模型上下文。失败实验的重复建议收到结构化计划修正反馈，最多两次，仍受原轮数预算约束。
- 提交时被取消或发生未分类异常的动作保留未知状态与清理记录；确认外部终态后释放资源并清除待清理标记。
- 前端从运行快照的 `result` 读取运行 ID、状态与来源，修复真实运行误标为模拟运行的问题。未知来源单独标示。
- 用户主动发起的调查使用已持久化的工作流标识作为来源根，修复 Lyra MCP 提交时缺少来源元数据的问题；平台事件继续保留原事件来源根。
- 重复实验比较保留实际执行约束，排除来源事件、因果关联和资源票据等追踪字段，避免不同动作的关联 ID 导致同条件实验被误判为不可比。
- 模型配置、平台能力连接与事件通道分别展示。RabbitMQ 暂不可用时保持 API 与历史查询可用，并在后台重连。

验证包括默认/自定义预算、超过 10 分钟的虚拟时间测试、完整截止时限、启动恢复、提交中断后去重、计划修正反馈、事件通道故障，以及通过真实 MCP 传输执行的通用 v2 / Lyra v1 模拟测试闭环。浏览器核对默认 120 分钟、180 分钟转为 10800 秒、真实运行标记和事件通道提示；页面测试提交在执行前拦截。

最终回归：`285 passed`；ruff 与 JavaScript 语法检查通过。浏览器结果保存在 `data/local/reliability-browser-check.json`，截图位于 `data/workbench-qa/screenshots/reliability-*.png`。更新后的本机 API 已启动于 `http://127.0.0.1:8080/`，RabbitMQ 未运行时页面明确显示事件通道不可用。

这些检查不代替真实游戏验收。本次检查时，平台/MCP/RabbitMQ 端口均未运行，且 `E:/unreal/Project/LyraStarterGame/Saved/StagedBuilds/Windows/LyraStarterGame/Binaries/Win64/LyraGame.exe` 不存在。没有把协议模拟结果计为真实游戏执行。

平台单次运行超时与调查时间预算是独立约束。Lyra MCP 未显式指定 `action_constraints.timeout_seconds` 时仍使用原有单次默认值；需要较长单次测试时，应同步配置该约束。
