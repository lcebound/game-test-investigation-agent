## 修改前的问题与现在的行为

上一批只有进程内分片锁与最终收据。模型调用期间进程退出，数据库里没有本次待完成请求；不同进程也无法判断对方是否已开始评估。

现在每个会话、用户、请求键拥有一条持久评估记录：

1. 在短事务内锁定会话根，检查作用域、已有收据、归档与输入，保存原请求和首次评估占用。
2. 事务提交后，按原有规则优先机制判断；必要时才调用轻量模型。规则路径同样使用持久请求身份，但不额外调用模型。
3. 其他执行实例遇到有效占用返回 HTTP 503、`Retry-After: 1`。工作台既有错误分支保留草稿、待发送请求与同一幂等键，不把它当作新消息。
4. 取消或异常只将自己仍拥有的代次标为可重试；释放失败时由截止时间兜底。进程直接退出留下的占用也可在过期后接手。
5. 重试接手增加代次并生成新令牌。旧调用不能完成、释放或覆盖新一代。新一代已提交收据时，迟到请求只返回该收据。
6. 第三次评估仍中断后，下一次请求不再评估，直接形成“评估多次中断”的澄清收据。恢复由同一请求键的再次调用驱动，不在后台自行轮询。

原始请求在模型调用前独立保存，模型方案不能替代它。相同键不同原文，即使尚无最终收据，也会被拒绝。评估状态为完成但缺少收据，或记录状态不合法时，不擅自重新评估。

## 提交复核与策略身份

新增的轻量协调服务集中处理评估领取、结果复核和收据，工作台 API 仅负责鉴权、请求身份及错误映射。

所有成功的语义提案均携带内部任务目录指纹，包含 `current` 和 `new_task`。写收据前重读有界目录，任务头、状态、目标或目录完整性发生变化即转为澄清，不再只复核跨任务提案。内部指纹不会返回浏览器或作为用户指令投递。

语义当前任务与跨任务结果都重新检查终态和墙钟预算。确定性地址仍保持原有显式续查行为。路由依然不启动 Worker，不决定日志读取或补测，不扩大预算或权限；实际发送继续通过原有任务接口与 Outbox。

评估保存提示版本、模型配置、超时和供应商参数组成的策略指纹；本实例等待期间配置发生变化时，旧提案转为澄清。已完成收据仍按原请求返回，不随新配置重新解释。滚动部署中尚未过期的旧实例可能按其原策略完成，占用被新代次接手后才由代次严格阻止旧结果；没有宣称实现全局即时策略撤销。

会话元数据修改也在事务内锁定会话根，使归档与路由收据在 MySQL 中遵循相同的锁顺序。模型等待期间不占用该锁。

## 数据迁移与兼容

- SQLite 迁移 22 新增 `conversation_route_evaluations`，旧消息收据继续可读、可直接重放；
- MySQL 新增 `018_conversation_route_evaluations.sql`，最低版本提高到 018，不修改历史迁移；
- 新表保存原请求、当前代次和占用，不把 Worker 上下文装进 Router，也不将原文返回额外的公开查询接口；
- NativeMemory、冻结契约及模型依赖不变；原有语义路由开关默认关闭。

SQLite 按现有初始化流程升级，MySQL 继续使用既有迁移工具。不能让旧版本与新版本同时处理同一消息：旧版本不识别新占用。没有主动操作用户现有数据库或重启服务。

## 仍然存在的边界

占用截止时间覆盖本次评估总超时，并保留 5 秒提交余量，使用执行主机的 UTC 时间。多主机需要时钟同步；这不是跨时钟故障的共识协议。

代次隔离保障本地有效占用与收据提交，不保证供应商推理恰好一次。旧请求在供应商侧继续执行、占用过期后新请求接手时，仍可能产生重复费用。当前 usage 审计只属于形成最终结果的调用，不是跨崩溃代次的完整供应商账单。

这次实现的是路由评估占用，不是调查 Worker 的跨进程推理所有权。通用事件合批、后台到期恢复、退回输入语义再评估、跨任务技术归纳以及真实模型质量/成本评测仍待完成。
