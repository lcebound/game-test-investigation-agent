# Agent 工程审查与优化（2026-10-17）

本轮针对目前实际使用的原生 MCP 调查流程。模型继续使用现有配置的 `qwen3.8-flash` 和固定兼容接口，平台工具沿用原始 MCP Schema 和返回内容。

## 与成熟 agent 的差距

对照依据：[Codex CLI 官方说明](https://learn.chatgpt.com/docs/codex/cli)、[OpenAI 上下文与证据管理示例](https://developers.openai.com/cookbook/examples/agents_sdk/building_reliable_agents_memory_compaction)、[Claude Code 工作原理](https://code.claude.com/docs/en/how-claude-code-works)。这些资料说明了工具执行与验证、可继续的会话、用户中途引导，以及上下文和可靠证据的分工。下表中的项目判断来自本地代码审查，不代表对竞品做了相同任务的性能测试。

| 方面 | 项目原有问题 | 本轮处理 | 剩余差距 |
|---|---|---|---|
| 用户引导 | 接口保存了补充内容，原生调查没有读取；`notify_event` 为空 | 每个模型边界读取补充；新输入使正在生成的旧答案失效；界面标记已用于调查 | 尚无模型文本逐字流式输出 |
| 失败修正 | 参数 JSON、Schema 或工具连接出错会使整轮调查失败 | 返回不含上游凭据的修正反馈；未知工具不执行；模型连接故障有限重试 | 模型不理解工具业务语义时仍可能无法完成 |
| 收敛与预算 | 只缓存部分平台调用，本地检索会重复；混合批次的一次重复可误触发停止 | 统一缓存；统计新证据与新读取范围；连续两轮无进展时转报告；新增显式报告提交动作 | 不能保证模型在最少轮次内找到足够证据 |
| 上下文 | 历史裁剪可能丢失证据 ID；长关键词曾存在反复压缩风险 | 固定证据目录、命中原文和最近用户输入；保留完整调用组与有效 JSON；上下文超限时进一步缩减 | Token 预算仍是估算，长会话未做完整语义摘要 |
| 重启恢复 | 只恢复部分证据预览，调用历史与检索进展丢失 | 保存有作用域和内容哈希保护的工作状态；报告草稿可在发布中断后恢复 | 工具执行与检查点提交之间发生崩溃时，只读调用可能再次发生 |
| 报告可信度 | 无效引用被跳过，模型总结仍可发布 | 发布前检查引用属于本调查且逐字存在；不合格时修正或输出证据不足报告 | 原文核对不证明总结的语义蕴含，也不证明因果关系 |
| 混沌实验 | 20ms 查询阈值与 120ms 卡顿冲突，容易被解释成游戏缺陷 | 明确区分预期注入影响、异常与未知；没有显式实验预期时保持未知；假设单列为待验证 | 来源平台仍按测试失败发送事件，需要平台侧提供业务实验预期后才能可靠区分通知策略 |
| 可观察性 | 原生模式缺少实际用量，前端出现无计划错误提示 | 展示累计输入/输出 Token、模型响应和缓存复用次数；历史统计不受最近 100 条事件分页截断 | 缺少系统化成本上限、延迟分位数和长期质量看板 |
| 根因与修复闭环 | 当前授权工具主要读取运行和观测结果 | 保持只读边界，报告不提升为根因确认或修复验证 | 还需原生 MCP 日志、调用栈、源码和受控补测工具，以及相应验证流程 |

## 修复的关键实现

- `workflows/native_mcp.py`：工具错误反馈、引用校验、实验判读、报告提交、用户引导、连接池及报告草稿恢复。预算不少于六轮时，末尾三轮留给报告与引用纠错；更小预算保留最后一轮。
- `workflows/native_context.py`：工作状态保存与恢复、固定证据目录、上下文压缩、检索范围和无进展检测。
- `api/app.py`、`api/workspace.py`：活动调查收到新输入后通知所有者；聚合原生模型用量。
- `storage/repository.py`：一次查询获取多种遥测事件，避免逐项统计增加数据库往返。
- 前端：显示原生流程用量、补充内容的处理状态、观察级结论及原文引用，区分来源测试与 Agent 发起的补测。

## 实验预期的显式输入

可通过现有调查约束传入：

```json
{
  "experiment_expectations": {
    "expected_effects": ["卡顿注入期间允许查询响应暂时超过正常阈值"],
    "violation_conditions": ["停止注入后故障仍 active", "客户端崩溃", "关键状态无法恢复"]
  }
}
```

这是调查目标的元数据，不要求平台实现新的工具契约，也不转换原始 MCP 数据。缺少这些明确预期时，报告保留 `unknown`。引用核验只检查原文一致性；报告仍为 `observation / inconclusive`，不会自动宣称代码根因或修复成功。

## 验证范围

新增回归覆盖：参数与连接错误修正、伪造引用拒绝和修正、中途用户纠正、进程中断恢复、报告发布中断、重复检索收敛、检查点作用域隔离、长查询压缩、模型超时、实验预期判读、累计遥测和提前提交报告。

真实模型回归使用已有真实混沌运行 `90b82915-e4e2-416c-9510-28a4c20613fa`。这是历史运行复核，不是新的故障注入或修复验证；模型调用与 MCP 读取均为真实调用。结果和本轮检查数量在完成后记录于 `data/local/review-20261017-result.json`。

最终验证：309 项全量测试通过；Python 静态检查、JavaScript 语法、桌面与移动端浏览器检查通过。真实模型复核完成于调查 `inv-426e27367d0343d9b8345f8a54a053a8`，使用 10 轮模型响应、67,900 输入 Token、3,340 输出 Token、14 次读取和 1 次读取复用，5 条引文通过核对。[查看复核报告](http://127.0.0.1:8080/#conversation=inv-426e27367d0343d9b8345f8a54a053a8)。

报告指出 20ms 阈值与允许 120ms 卡顿的实验预期存在冲突，并保留恢复与因果方面的待验证点。实验分类仍是模型评估，不能作为确定的业务故障判据；本轮也没有修改平台的自动通知规则。结束点受预留报告轮次影响，不能将本次 10 轮直接解释为模型已能自主高效收敛。

尚未开展相同任务、相同模型、相同输入和多次重复的竞品基准测试。不能用单次回归的 Token 或耗时证明已达到 Codex、Claude Code 的能力水平。
