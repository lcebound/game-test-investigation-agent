# Harness 第一批实现：有界输入、Spill 与调查内召回

日期：2026-11-02。对应[渐进改造方案](super-agent-migration-plan-2026-11-02.md)与[上下文和召回设计](harness-context-and-recall-design-2026-11-02.md)。

本轮在现有 Python 原生调查路径实现 P0 与部分单 Worker 的 Spill/Recall，不引入 DSH、另一套运行时或新的数据库。

## 已实现

### 用户补充的有界表示与回读

完整输入继续存放在原有 workflow_command_outbox。NativeMemory 持有带 SHA-256、原文大小、截断标记和 read_ref 的卡片，不再把每条最多 6,000 字符的正文反复加入工作消息。

工作消息显示首条与最近三条补充，并给出 inputs 目录、隐藏数量和未完整召回数量。中间补充、截断部分可以分页回读；这不等于已经实现自动归并所有有效约束的 TaskBrief。

新增 agent_read_context：

- ref=inputs：按 offset/limit 读取本调查的输入目录，目录响应受字节上限约束；
- ref=input/<command_id>：读取完整原始补充，支持字面 query、UTF-8 byte_offset/max_bytes 和 expected_sha256；
- ref=evidence/<evidence_id>：复用现有证据读取与来源校验。

工具只读取当前调查。用户输入保持其来源身份，不变成独立游戏证据；目录外的调查 ID、任意文件路径和其他调查的输入不能通过这个入口读取。

召回使用现有读取预算预留、调用身份、缓存与结果持久化。相同读取复用缓存不重复计费；重启时可以从已保存的调用结果恢复输入读取范围，不必再次执行工具。

### 大段工具结果 Spill

超过 4,096 UTF-8 字节的原生平台响应仍完整存入原有不可变 Artifact，并进入 Evidence 账本；模型首次只收到最多 1,200 字节的连续原文预览，以及 read_ref、完整哈希、片段哈希、总大小和续读字节位置。

预览不再把不相邻首尾拼成一段。证据搜索与原文读取继续可用，不因为 Spill 降低来源校验或提升结论等级。

为避免额外 Schema 挤占小窗口，存在用户补充时才向模型展示通用召回工具；没有用户补充时，长证据继续使用已有的原文读取/搜索工具。内部证据引用仍可由通用入口解析。

### 追问驱动工具展示

性能/崩溃诊断工具的展示同时检查原始目标与完整的权威补充输入，而非只看原始目标或卡片预览。即使关键词位于被截断部分，相关工具也可展示。

这是工具可发现性改进，不会自动执行诊断、提交测试或扩大平台权限。候选选择器也可以校验召回动作，保留原来的建议与实际执行分离。

### 报告上下文和输入覆盖

报告上下文沿用独立收尾路径，但输入改为有界卡片，移出的原文保持可回读。收尾阶段仍禁止额外取证，保留已有 Token/费用预留。

若存在未完整召回的补充，程序在最终报告中添加覆盖限制，不能把有限结论呈现为覆盖了所有用户要求。读取覆盖只说明工具读取过哪些字节，不代表已经验证了自然语言要求的解释。

原文搜索未命中的提示明确限定为所请求字节位置之后，不把局部未命中说成整份材料不存在。

## 检查点与交付

新检查点版本为 3，读取器兼容版本 1/2/3。旧输入预览在恢复时重新绑定到完整输入账本。

新增的输入读取范围随检查点保存；调用结果先于检查点保存时，恢复过程可以补齐范围，并核对输入来源哈希。

API 与 Worker 应使用同一版本。回退到旧代码前，需要备份并处理版本 3 检查点；旧版本不保证能读取新增状态。

本轮没有安装包到全局环境，也没有重启现有服务。使用 scripts/start_workbench.ps1 的服务从源码加载，重启后采用新代码；独立安装部署可以使用本轮构建的 Wheel。

## 验证

- 被窗口省略的中间输入、目录分页、中文原文重组；
- 当前调查归属、哈希检查、缓存复用、调用 ID 与预算；
- 大结果隐藏字段的召回，连续原文和字节位置；
- 长输入报告封套、旧检查点升级；
- 关键词位于截断输入之后的工具展示；
- 读取完成、下一次检查点前中断后的恢复；
- 预算压力下的有限报告及输入覆盖限制。
