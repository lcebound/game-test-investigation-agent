# 第十三批：会话消息的轻量语义路由

日期：2026-11-03。延续[第十二批 Worker 退回](harness-phase12-implementation-2026-11-03.md)，补齐工作台消息入口的自然语言归属判断。复用原有任务短卡、ModelGateway、模型并发限额、消息收据及投递入口，没有更换 Worker 执行器。

## 参考与本批范围

重新核对固定版本 deepseek-ai/dsh-superagent-prototype@6337fc823ce20251c8de8085948165c81aaa701e 的 [orchestrator 提示](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/6337fc823ce20251c8de8085948165c81aaa701e/prompts/orchestrator.md)与 [Evals](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/6337fc823ce20251c8de8085948165c81aaa701e/src/core/evals.ts)。借鉴协调者只接收短卡、不替 Worker 调查、已有归属直达、宿主重新校验和请求身份与决定分离的机制。这是 Python 行为实现，没有复制或逐行翻译上游运行时。

本批处理用户通过工作台 `/messages/route` 发送的消息；平台反馈仍按既有订阅直接送达。Worker 退回后的自动重归属仍沿用第十二批的明确地址规则，没有把所有退回输入或外部事件接入模型评估泵。

## 如何启用和使用

同时配置 `GTA_ENABLE_MODEL=true`、`GTA_ENABLE_SEMANTIC_ROUTER=true`；只有 API 凭据不会自动启用。默认保留规则模式。`GTA_ROUTER_TIMEOUT_SECONDS` 默认 10 秒，可设置为大于 0、不超过 60 的有限数值，涵盖容量等待与模型调用。没有主动修改本机配置或重启已有服务。

- 明确编号、带分隔符的任务名称及“新任务：”仍走确定性规则；未知名称或残缺引号不会被模型绕过。
- 有当前任务时，普通补充和纠正继续交给该 Worker。包含“刚才”“回到”“另一个”“另外”“单独”等指代或独立意图的消息才进入可选语义研判。
- 没有当前任务且没有明确地址时，可通过短卡研判归属。
- 模型只提议 `task/current/new_task/clarify`。跨任务归属或新任务意图必须带原消息中的短引用；引用不匹配直接澄清。同名任务不会因为模型选中了其中一个就被认为已唯一定位。
- 新任务目标使用用户原消息，不使用模型生成的执行方案。调查开始仍复用原任务创建接口及其预算、条件和权限检查。

提示要求区分具体指代与主题相似，也要求“上一个”没有可核验依据时澄清。短卡不包含完整时间线，不能据卡片排列或任务编号推断先后。原文短引用只能校验来源存在，不能确定性证明模型理解了用户意图；真实语义质量仍需要模型评测。

## 上下文、预算与接口适配

语义评估只读取本条消息、当前调查编号及最多 20 张本会话任务卡，卡片包括任务身份、当前调查编号、原始目标短表示和状态。目录不完整时不调用模型，不以截断目录中的唯一匹配代替全会话唯一匹配。没有读取 Worker 对话、报告、日志、检查点或原始 Artifact。

通过现有 ModelGateway 使用共享模型容量，每次最多一次应用层调用，关闭 SDK 自动重试；支持 Chat Completions 和 Responses 的 JSON Object 请求，本地严格校验返回结构，不提供工具。模型兼容性不满足时返回澄清，不隐式换协议或追加调用。

最多输出 512 tokens，并受原配置的输出上限约束。单次总 token 上限不超过 16,000，且同时受已有模型总 token 上限和上下文窗口限制。调用前按包含提示和消息的 UTF-8 字节数保守估算输入上界，校验 token 与已配置的成本限额。此保守估算可能使长消息直接进入澄清。预算属于单次路由请求，不消耗或增加某项调查的取证预算，也不是累计会话额度。

提供者专有参数仍可复用，但不能覆盖路由消息、模型、工具、输出上限或引入历史会话。Responses 显式设置 `store=false`。返回截断、工具结束或不合法结构均不能变成路由决定。可取得 usage 时，失败输出同样由 Gateway 记账；缺少 usage 时按调用前输入上界及输出上限估算。传输失败或硬超时后未取得的提供者实际用量不能被当作已知零成本。

路由收据只保存调用次数、输入/输出 tokens 和估算成本，不保存模型推理、短引用、原始异常或凭据；原始用户消息仍单独保存。没有把供应商错误文本展示给用户。

## 幂等、状态变化与执行边界

模型等待位于数据库事务之外。请求先检查已有收据，等待结束后再开启短事务、锁定会话根、重查收据及归档状态。进程内使用固定 64 个分片锁合并相同请求的并发重试，不随请求量持续增加锁对象。

评估结束后重新读取任务目录；目录或状态变化时返回澄清。写收据前再次核验语义目标仍为该任务头、状态与目标短表示未变，且未超过墙钟预算。已完成、失败、取消中或已取消的任务不会因模糊语义引用自动继续。明确地址仍保留既有续查入口。

同一请求键重试返回固定收据，不重新调用模型；相同键不同消息冲突。路由接口不创建任务、不输入补充、不启动 Worker。实际投递仍经过原有鉴权、任务头、预算、Outbox 和幂等检查。

进程崩溃发生在模型返回与收据提交之间，重试可能再次评估；多进程同时首次收到相同键也可能各消耗一次模型调用。最终收据通过现有事务串行化，不能据此宣称提供者调用恰好一次或跨进程 Worker 所有权已实现。需要持久评估租约的通用批处理器仍属后续工作。
