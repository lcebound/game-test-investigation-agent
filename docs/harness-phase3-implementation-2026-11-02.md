# Harness 第三批实现：问题账本、证据关联与逐项复核

日期：2026-11-02。接续[第二批字段召回](harness-phase2-implementation-2026-11-02.md)，实现[渐进方案](super-agent-migration-plan-2026-11-02.md)中 P1 的问题状态、反证/缺口关联及简单任务计划优化。

本批直接扩展现有 InvestigationPlan、Evidence 索引、事件日志和报告发布流程。没有增加另一套问题数据库、模型工具或人工调度步骤；平台取证与候选选择继续由现有 Agent 和判断逻辑完成。

## 已实现的行为

### 一项问题也能开始调查

原先首次读取前要求 3–5 步计划，现在允许 1–5 个问题项。简单任务只需一项；复杂调查仍可分解为多个问题。首次读取前保存计划、单个进行中步骤、版本检查和计划修改规则继续保留。

没有自动将任意自然语言目标拆成完整需求清单；问题仍由模型提出。一次回复仍可顺序调用计划、取证，不强制增加一个模型轮次。

### 使用现有计划承载问题账本

step_id 就是 question_id。已有 question、evidence_needed、completion_condition、evidence_ids、outcome 继续分别承载问题、所需证据、完成条件、支持引用和答复草稿；新增可选字段：

| 字段 | 含义 | 边界 |
| --- | --- | --- |
| counterevidence_ids | 与问题关联的反证引用 | 最多 10 项，必须是本调查当前可读证据 |
| remaining_gaps | 尚未解决的证据缺口 | 最多 4 项，每项 1–300 字符 |
| source_input_ids | 提出或修订此问题的原始补充来源 | 最多 10 项，必须属于本调查 |

所有证据/输入引用 ID 限制为 1–256 字符，完整计划继续受 10,000 UTF-8 字节限制。新增空字段不重复写入计划；修改时省略字段会保留原值，显式传空数组才会清除对应引用或缺口。

例如在已有计划中记录部分答案：

```json
{
  "expected_revision": 1,
  "reason": "已有失败观测，尚缺独立恢复证据",
  "steps": [{
    "step_id": "recovery",
    "status": "in_progress",
    "evidence_ids": ["<本调查证据ID>"],
    "counterevidence_ids": ["<本调查反证ID>"],
    "remaining_gaps": ["缺少独立恢复观测"],
    "source_input_ids": ["<本调查补充ID>"],
    "outcome": "目前只能说明清理回执已返回，不能判断恢复成功"
  }]
}
```

模型状态与程序派生的问题覆盖分开处理：

- open：尚无答复或关联证据；
- partial：已有部分材料，或计划虽标记 completed，但仍有缺口、不可读证据或输入尚待复核；
- answered：模型记录了 completed、答复和可读支持引用，且没有已声明缺口或待复核输入；
- blocked：计划标记 blocked/skipped，保留受阻或跳过说明。

answered 是模型判断，不是程序验证了自然语言答复，也不等于目标通过、恢复成功或根因确认。反证引用会保留；其语义冲突是否已解决仍需模型解释，未解决部分应明确记入 remaining_gaps。程序不通过“存在一个引用”证明答案正确。

### 新追问按问题项复核

程序将当前全部补充的 command_id 与原文 SHA-256 合成为输入指纹，并为每个被明确更新的问题记录复核时使用的指纹，不复制完整输入。

新补充到达，或者同一补充的内容发生变化后，旧答案会显示 needs_review；已完成项的覆盖状态回到 partial。更新一个问题只刷新该问题的复核标记，未更新的问题仍待复核。输入没变、计划内容也没变的重复修改继续拒绝。

这是一种保守失效策略：新输入可能影响所有问题，程序不自动猜测哪些自然语言要求无关。模型可在一个计划修改调用中复核多个问题；标记复核仍是模型声明，不证明它已理解所有要求。第一批的未完整召回输入限制继续生效。

修改已完成问题的 question、evidence_needed 或 completion_condition 时，必须显式重设状态；如果仍要保持 completed，必须同时提交 evidence_ids 与 outcome，避免改了问题后静默继承旧答案。

### 将问题关联接到现有取证与选择逻辑

证据目录增加 question_ids、counter_question_ids，沿用已有 read_ref 和来源元数据，构成轻量的问题—证据关联视图。问题反证纳入目录保留与摘录优先级；现有笔记字节上限和关键证据省略提示继续有效。

出现答案、反证或显式缺口后，工作上下文提供简短 question_coverage 与 next_question_id，不重复复制问题全文或答复。提示优先沿用进行中项，再考虑尚可推进的未回答项；它不执行平台操作。

问题 remaining_gaps 纳入原有候选选择器。即使没有竞争假设，也可以针对问题缺口比较合法动作；仍使用现有的 Schema、预算、缓存与权限检查，选择不会直接执行工具。单纯改写 outcome 或缺口文字不会重置问题进展判定。

### 报告与工作台保持覆盖状态一致

报告发布时从最新计划事件、当前输入账本和可读证据重新构建问题进展，不依赖进程内 NativeMemory。报告列出各问题状态与未核实答复草稿；未回答、受阻、待复核、不可读证据和显式缺口会写入 unresolved_questions。允许产出有限报告，不强迫将所有问题标为 answered。

问题进展不生成事实 Claim，也不改写 ObjectiveEvaluator 的验收结果；原有引文与结构化字段核验继续独立执行。

工作台快照增加 native_runtime.question_coverage，沿用现有调查范围鉴权。界面显示部分回答、新补充待复核、来源补充、缺口及反证入口；已不可读的证据按钮禁用。旧快照继续使用原状态显示。模型文本通过现有 textContent 路径渲染。

## 验证

新增 tests/test_native_questions.py，20 项离线测试，覆盖：

- 1/2/5 项计划、8,192 Token 配置窗口下的单问题完整调查；
- 非法/跨调查引用、字段边界和修改失败的原子性；
- 新补充失效、逐项复核、相同输入 ID 内容变化和检查点恢复；
- 旧计划兼容、completed 与显式缺口不一致、证据不可读；
- 反证目录与摘录保留、文字改写不算进展；
- 修改已完成问题时重审答案；
- 问题缺口复用候选选择器且不读取平台；
- 无 NativeMemory 时从事件重建报告缺口；
- 工作台当前覆盖状态与跨项目访问隔离。

原有“单步计划必须拒绝”的用例改为“空计划必须拒绝”，另有新增正例验证单问题合法。其他既有调查、召回、报告与安全边界回归保留。

Microsoft Edge 无头浏览器使用实际 renderExecution 函数和隔离快照检查了待复核样式、缺口展示、反证跳转、过期证据禁用、文本转义及旧快照兼容，结果通过。记录与截图位于 data/local/harness-phase3-browser-20261102/。这是面板渲染检查，不是完整工作台 E2E。
