# V4 架构回归修复

日期：2026-09-23。此次修改针对通用运行链路，不修改既有 V3/V4 在线验收记录或冻结清单。

## 修改内容

1. **动态实验节点**：已接受的实验决策在已有采证节点完成后，可以追加独立节点。追加需要引用已验证的证据，沿用能力绑定和计划预算校验；在途运行须先查询，失败节点需要显式计划增量。已完成节点保持历史身份，不重置为 ready。
2. **执行计划与推理快照分离**：动作规划读取已接受 PlanDelta 对应的执行计划，原始 ContextSnapshot 不修改。额外节点 ID 由决策 ID 确定，计划落库后、动作落库前中断可以恢复，不重复追加节点。
3. **跨版本运行投影**：保留节点继承先前计划版本的动作历史；计划增量不能替换或人为改写已绑定动作的节点状态。拒绝与已接受决策不匹配的计划版本。
4. **投影一致性**：目标评估、摘要和来源图仅在同一稳定事件游标区间内完成后才写 checkpoint。遇到并发更新有限重建，持续变化时返回 ProjectionLagError，不把旧结果标成最新。
5. **最终上下文预算**：ProjectPack、摘要、manifest 和预算元数据一同计入最终序列化估算。优先裁剪可选内容，同步更新 manifest；必需状态超限时保留状态并在内核停止，不向模型发送超限上下文。此处仍使用保守字节估算，并非供应商实际 tokenizer 计数。
6. **失败报告**：规划/执行失败时，摘要优先说明中断原因和未完成目标，同时保留真实 Run 判定；失败报告仍可以正常发布。
7. **格式整理**：对 src、tests、scripts 运行 Ruff 格式化，修复先前格式检查未通过的问题。除上述逻辑修改及新增测试外，其余格式化文件不改变业务意图。

## 新增本地回归覆盖

- 编译计划后分别执行 1、2、3 次独立运行，并正确结束；不同运行返回相同字节仍保留独立观测。
- 第二轮追加计划已保存、动作尚未保存时模拟中断；重新构造规划服务后恢复，节点、动作及提交不重复。
- 同一轮新增 PlanDelta 后立即创建动作，绑定新节点且不改写原始快照。
- 旧计划版本的动作在新版本继续投影，已执行节点不能被替换。
- 投影构建期间插入新事件，以及持续变化时拒绝发布新鲜 checkpoint。
- 超大 ProjectPack 的裁剪、manifest 对齐、完整序列化预算核对及必需状态超限处理。
- 失败摘要明确目标缺口，同时保留平台通过判定。
