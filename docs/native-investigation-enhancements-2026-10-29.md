# 原生 MCP 调查能力与稳定性改进

本次改动面向 `GTA_MCP_NATIVE_TOOLS=true` 的本地调查流程。真实任务评测、真实模型对照、游戏补测与故障注入按要求暂缓；自动化回归和浏览器检查均使用隔离数据或模拟响应。

后续原生流程已支持 Temporal，见[运行与交付改进](runtime-and-delivery-2026-10-29.md)；最新排队、诊断及真实依赖验证见[调查执行优化](optimization-and-dependency-checks-2026-10-31.md)。

## 证据来源

Provider 可以按工具配置 `native_source_fields`，使用 JSON Pointer 从**保存的完整原始响应**中提取来源旁注。平台工具参数和返回正文均不改写。例如：

```json
{
  "provider_id": "lab",
  "url": "https://lab.example/mcp",
  "project_ids": ["game-a"],
  "allowed_tools": ["read_run"],
  "native_source_fields": {
    "read_run": {
      "run_id": "/run/id",
      "build_id": "/build/id",
      "environment": "/environment/fingerprint",
      "timestamp": "/collected_at",
      "phase": "/experiment/phase"
    }
  }
}
```

路径应根据实际 MCP 响应配置，不能照搬示例猜测字段。仅提取非空、有界字符串；时间必须有时区。缺失、类型不符或非 JSON 响应保留未知。运行身份包含 provider，避免不同平台的同名 run 被当成一次运行。

旁注保存在 `mcp.native.tool_completed`，进入工作上下文和工作台证据卡片。它固定标记为 `provider_declared`，不把原生证据升级为真实执行、可信 Fact 或已验证根因。未配置映射的原有 Provider 继续可用。

## 检索与报告

- `agent_search_evidence` 支持跨证据字面/正则检索，以及 provider、运行、构建、环境、阶段和产物时间过滤。一次最多扫描五份证据、合计 4 MiB；每份最多 2 MiB，返回最多二十条有界原文和续读游标。存在游标时不得把未命中解释成整份产物不存在该内容。
- 正则在可终止的独立 Python 子进程运行，最长两秒，并服从调查剩余时间。字面检索保留分块边界重叠；正则仅保证当前扫描分块内的匹配。时间过滤针对产物来源时间，不是产物中每行日志的时间。二进制或非 UTF-8 内容需交给适用的分析工具。
- 正则/字面命中保留来源和 UTF-8 字节位置，进入正常证据读取审计及固定笔记；仍可用 `agent_read_collected_evidence` 精确读取。
- 新报告使用 `findings`，每条含 `finding_id`、`text`、独立 `citations`、`scope` 和限制，可声明运行、provider、构建、环境与阶段。主张声明的来源须与每条引文一致。跨运行比较必须明确声明，并有完整、相同的构建和环境。
- 发布前检查引文归属与字面存在、常见度量值及单位换算，以及“每帧”“总是”等频率扩大和根因/修复措辞。发布摘要由逐条 findings 生成，报告保留逐条主张及其引用。
- 兼容旧 `summary + citations` 格式，但明确增加缺少逐条主张绑定的限制。历史检查点仍可恢复。

这些是确定性的一致性检查，**不是完整的语义蕴含、统计有效性或因果证明**。无法覆盖所有自然语言中的次数、时间范围和措辞。报告继续保持 `observation / inconclusive`，不会因模型填写了来源或支持状态而升级结论。

## 假设与下一步选择

`agent_update_hypotheses` 使用现有 `Hypothesis` 和共享假设账本，记录可证伪预测、支持证据、反证、缺口和建议验证动作。新假设从 revision 1 开始，后续逐版递增；批次在同一事务内校验和写入，陈旧版本、跨调查引用、不可读证据和同一证据同时支持/反驳均被拒绝。最多保留十个假设。

`supported/refuted` 是模型调查评估，不是独立验证；原生流程不能提交 `confirmed`。假设从权威账本恢复，不依赖被裁剪的对话历史。工作台显示预测、缺口及支持/反驳证据入口。

`agent_choose_next_action` 最多比较三个建议，验证可用工具、原始参数 Schema、证据归属、假设和缺口名称、读取/分析作业额度及缓存。复用现有 `CandidateSelectionService` 的可观测预测判别逻辑，按证据缺口、可区分的假设对和操作成本层级排序，记录选择与未入选原因。它只返回建议，实际调用仍经过原来的权限、审批和预算检查；不会接通新的平台写操作或自动运行游戏实验。

收敛判断区分账本变化与新读取范围。只有新内容时最多给予三轮取证推进额度，避免持续变化的无关日志维持调查；连续两轮无推进先给予一次调整方向的机会，仍无推进再转报告。文字改写和已见过的状态不能反复重置检测，原来的总轮数与报告预留仍有效。

## 预算、失败与恢复

原生工具调用响应封装通过共享 `ModelGateway` 验证，模型 SDK 隐式重试关闭；一次尝试占用一个持久轮次，重试服从调查截止时间。认证/配置错误直接结束，限流、连接及超时错误分类记录并有限重试，响应格式错误会收到不含上游敏感信息的修正提示。

新增环境变量：

| 变量 | 默认 | 作用 |
| --- | --- | --- |
| `GTA_MODEL_MAX_TOTAL_TOKENS` | `250000` | 每项原生调查的累计模型 Token 上限 |
| `GTA_MODEL_MAX_ESTIMATED_COST` | 不启用 | 每项原生调查的累计估算费用上限 |
| `GTA_MODEL_COST_PER_INPUT_TOKEN` | `0` | 运维提供的每输入 Token 价格 |
| `GTA_MODEL_COST_PER_OUTPUT_TOKEN` | `0` | 运维提供的每输出 Token 价格 |

启用费用上限时必须同时配置正的输入、输出单价，币种由部署配置保持一致。系统不查询或猜测供应商价格。

模型调用前按输入 UTF-8 字节上界与最大输出预留预算，返回后用供应商用量结算。没有用量时保留保守估算，超时或进程中断后未结算的请求保留整份预留。因此剩余额度接近上限时，可能提前拒绝一次实际费用较低的请求；这是显式的保守边界。旧调查的成功响应用量也计入统计。

读取调用在外部执行前原子保存调用 ID 和参数身份摘要并预留次数，结果单独保存为有作用域/内容哈希保护的 Artifact。重启时，即使对话检查点未提交，也能恢复已保存结果；重复调用 ID 不能用新参数绕过读取限额。SQLite 使用事务，MySQL 使用调查行锁。外部读取已返回但尚未完成结果持久化的极小中断窗口仍可能需要重新读取，不能宣称外部系统的 exactly-once。

Provider 发现失败会记录明确缺口，其他来源仍可继续。缓存按当前用户输入失效，完成的本地不可变读取可复用；平台读取维持三十秒缓存期。来源撤销或工具 Schema 变化仍通过现有 Provider 准入检查处理。

工作台显示累计 Token/费用预算（含未结算预留）、假设、最近比较的问题和证据来源。配置与代码更新需要重启既有服务进程后生效。

## 验证边界

新增离线回归覆盖来源指针、跨运行/构建混用、单位换算与过度推断、逐条主张发布、跨文件中文检索及分块边界、游标、正则超时、假设批次回滚、候选校验、持续无关新内容、Provider 故障、认证/限流、格式异常、Token/费用预留和读取结果恢复。

浏览器检查使用隔离数据库、合成证据及模型替身，检查桌面/390px 移动端、预算和假设/来源展示、无横向溢出及无 JavaScript 异常。没有调用真实模型或测试平台，也没有执行游戏任务。全量回归结果记录在任务完成说明中；依赖 Windows 实际沙箱的跳过项不视为隔离验收。
