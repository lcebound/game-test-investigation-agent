# 代码复核与执行边界完善（2026-09-23）

本轮重点复核调查控制器、持久化动作规划、计划校验、预算计数、Temporal 活动、报告生成和真实测试入口。基于此前真实运行账本修复已确认的问题；不是对整个仓库的完整安全审计。

## 已完成修改

| 问题 | 修改后的行为 |
|---|---|
| 追加实验超出预算只显示 ValueError | PlanValidation 返回所需设备分钟与预算上限；规划层抛出专用 PlanBudgetExceeded。本地和 Temporal 均返回同一稳定原因码，并包含数值。拒绝发生在保存新计划、提交平台之前。 |
| 测试脚本默认预算可能不够完成重复性目标 | 提交前读取平台能力成本，检查最少运行数、模型轮数和设备分钟预算；预算不足时不创建调查、不提交 Run，不自动放宽用户预算。预检连接在成功和失败时均关闭。 |
| 本地重复查询同一动作复用轮询 ID | 每次等待调用拥有独立会话 ID，不同查询无法复用已有预算预留记录。 |
| Temporal 后续轮次复用同一轮询 ID | 新历史使用轮次与轮询序号联合标识；同一活动重试保持 ID 不变。通过 round-scoped-poll-budget-v1 patch 保留旧历史行为；旧活动参数仍可使用。 |
| 等待未取得结果时误用 max_rounds_reached | 每轮重新初始化执行结果原因，无终态结果时明确报告 external_result_pending；不据此宣称外部任务失败或已取消。 |
| 部分预算耗尽/等待未完成的报告只突出 Run 结果 | 报告优先说明调查中断、目标尚未完成，再列出已获得的运行观测。 |

预算口径保持保守的能力预估与预留额度，没有用短时间内完成的真实 Run 去推断可退还额度，也没有绕过执行层原有的预算限制。

## 验证边界与后续方向

本轮未运行新的真实平台任务，未进行 Temporal 服务端历史重放。此前冻结清单代表修改前的真实验收版本，原清单和记录保留；不能把此前真实运行当作本轮代码的在线验收。
