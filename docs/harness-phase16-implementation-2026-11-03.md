# 第十六批：Worker 退回输入的语义再分派

日期：2026-11-03。补齐[第十五批后台恢复](harness-phase15-implementation-2026-11-03.md)列出的“退回补充语义再评估”。复用第十二批不可变输入与转交 Outbox、第十四批持久评估占用及第十五批生命周期恢复器，没有引入新的业务表或模型运行时。

## 参考的协调机制

重新核对固定版本 deepseek-ai/dsh-superagent-prototype@6337fc823ce20251c8de8085948165c81aaa701e 的 [EnginePart.handBack/queueForEval](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/6337fc823ce20251c8de8085948165c81aaa701e/src/core/part.ts)；继续沿用已核对的 [Evals.handback/decide](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/6337fc823ce20251c8de8085948165c81aaa701e/src/core/evals.ts)。

采用的行为是：Worker 只退回确实收到的输入，协调层保留原请求和退回链，再启动有界评估；退回理由只是 Worker 的解释，不能成为新的用户授权；已经拒收的任务不能再次接收同一条原消息。实现为本项目的 Python 行为适配，没有复制或逐行翻译上游运行时。

## 新增行为

之前 Worker 退回后，只有原文包含可由规则唯一识别的明确任务地址，才会自动转交。其他退回消息都留在待处理区。

现在，在启用语义路由和后台恢复后，每轮额外扫描最多 4 条未完成评估的待归属输入。明确地址仍由第十二批同步规则优先处理；剩余消息可用任务短卡进行语义再评估，例如“回到刚才那个登录问题，补充这段日志”。

每次评估使用：

- 从原始输入账本核验的完整用户正文，最多 4,000 字符；
- 本会话有界任务短卡，排除整条退回链上的所有拒收任务；
- 原任务身份，以及最多 240 UTF-8 字节的 Worker 退回理由，明确标记为未核实判断。

没有加载 Worker 对话、证据、日志或计划。Router 不制定取证方案。模型若选择其他任务，仍须提供用户原文中的短引用，不能拿 Worker 理由中的文字代替用户意图。

仅剩一个其他任务不构成自动转交依据。无法定位的 `current`、歧义、未提供的任务编号、伪造引用以及模型不可用都保持待归属。模型即使提出新任务，也不会替原消息补出构建、预算、测试条件或创建授权，仍需要原有独立任务入口。

## 来源、占用与原子投递

每条退回记录使用自己的 `return_id` 作为评估键，在固定内部主体 `input-return-router` 下复用已有 `conversation_route_evaluations` 和消息收据。评估原始载荷只保存退回记录身份、修订、来源哈希与原始 trigger_id；正文继续沿不可变输入链读取，不复制 Worker 上下文。

该内部主体是协调服务的收据命名空间，不是新的用户权限。普通消息 API 生成的评估键始终为 `route-…`，不能通过用户传入的幂等键伪造退回评估。通用消息恢复器跳过内部 `return-…` 评估，交由专用恢复器处理，避免把来源元数据误当作聊天正文。

模型等待不持有数据库事务。提交时重新检查：

1. 当前评估仍拥有相同代次、令牌、策略与有效截止时间；
2. 退回记录仍未被处理，来源身份和修订没有变化；
3. 会话仍未归档、退回链未增加，原始正文仍与哈希一致；
4. 候选任务目录和任务头仍有效，目标未停止、未完成且未超过墙钟预算；
5. 目标不在已经拒收过该输入的任务集合中。

通过后复用 InputReturnService._attach：原输入保留相同 trigger_id 和来源，目标任务保持自己的权限、预算与调查条件。转交输入、退回状态、调查事件、评估完成和结果收据同事务提交。

转交在事务内使用保存点。候选目标冲突时撤销该次转交的全部写入，再保存待归属结果；收据写入失败则整个事务回滚，不能留下“已经发出但没有收据”的中间状态。未知存储异常仍按原代次释放与过期恢复，不假装转交成功。

人工明确转交或关闭待归属事项发生在模型等待期间时，以已提交的人工决定为准，旧模型结果记为已失效，不再另行投递。旧代次不能覆盖新一代已经完成的转交。

## 后台恢复与可见行为

沿用已有恢复配置，不新增开关：`GTA_ENABLE_MODEL=true`、`GTA_ENABLE_SEMANTIC_ROUTER=true` 且未关闭 `GTA_ENABLE_ROUTER_RECOVERY` 时启用。普通过期消息与退回消息分别最多处理 4 条，顺序处理，共享原模型容量和调用预算，不为积压消息无限创建任务。

有效占用和已形成收据的退回评估不会重复调用模型。取消、服务中断及过期接手继续使用有限代次：最多初次评估加两次恢复，耗尽后保持待归属。关闭语义路由时不领取新评估，也不留下阻止未来启用的完成标记。

已经完成但仍不明确的评估不会因每次轮询反复调用模型，也不会在目录变化后自动重判；消息继续显示在原有待归属区，用户可以明确转交或关闭。新的用户补充仍有新的身份，不受旧消息的拒收链限制。

超出路由窗口或来源不可核验的输入保留原文与审计记录，保存待归属结果，不截断原文后执行。深度损坏 JSON 的解析错误也被转换为不可核验来源，不让它反复打断整个扫描批次。
