# 通用证据判定与报告核验

日期：2026-11-02。对应[判断正确性审查](judgment-accuracy-review-2026-11-02.md)。实现未使用特定游戏、运行 ID、故障字段名或固定阈值。

## 验收规则

`ObjectiveEvaluator` 在调用内置或已注册规则前筛选证据：匹配请求的构建 ID、指定的修订、配置子集及环境，且证据必须可读取。事实引用的全部证据均须属于有效范围，不能只检查第一份。历史资料可保留，但不参与当前目标验收；目标范围内的有效失败样本仍正常判为失败。

同一运行的冲突数值、不同 `measurement_scope` 或混合来源不能被静默排除后让其他样本取得通过。它们产生明确缺口并保持 `insufficient`。不兼容的声明单位、布尔测量、非有限值、数字字符串及不明确的运行归属同样不会被当成有效数值；用户明确排除的模拟执行不会妨碍真实样本验收。

`constraints.objective_spec.fact_filters` 可显式选择事实 `data` 中的标量字段，例如 `{"phase":"baseline","window_id":"steady"}`。这是精确筛选，不猜测阶段、窗口或指标意义。不同指标名和统计量继续由原有配置决定。未配置目标构建或环境时维持原有可用性，不凭空要求额外字段。

修正后的评估状态修订加入判定策略版本，避免在同一来源版本下覆盖或复用旧结果。发布 `goal_met/goal_failed` 还必须具备与当前目标规则及结果一致的 assessment，并覆盖主目标；文本说明或模型标签不能替代验收。

## 结构化主张

新增通用 `EvidenceAssertion`，可用于原生 finding 和报告 Claim。它只描述不可变原始 JSON 中的字段与运算：

```json
{
  "evidence_id": "collected-evidence-id",
  "pointer": "/metrics/backlog",
  "operation": "value",
  "operator": "le",
  "expected": 12
}
```

必须同时引用属于本调查的原始证据，断言关联的证据 ID 不能超出引用集合。

- JSON Pointer 遵循 RFC 6901，支持转义和数组索引；拒绝负数、非标准索引和含歧义的重复 JSON 键。
- `operation` 支持 `value/count/min/max/mean/p50/p95/p99`，比较支持 `eq/ne/lt/le/gt/ge`。
- 布尔、字符串、null 与数值保持不同类型；不把 `false` 转成 0，也不把字符串数字转成数值。字符串保留原有空白。
- 运算使用精确有理数，避免大整数或循环小数被舍入成错误的相等判断。分位数使用 R7 线性插值，并在结果文字中标明方法；不能默认与其他统计方法等同。`eq` 是精确相等，近似值应使用有依据的上下界比较。
- 字段值、统计量、比较关系均重新计算。报告主张由程序生成，包含实际证据 ID、字段路径、运算结果和关系；模型不能为查询指标改贴帧耗时等另一个名称或单位。
- 发布服务再次独立读取原文核验；仅修改已生成报告文字或伪造验证状态不能取得结构化支持。

这项核验确认的是“指定来源字段与声明运算相符”，不确认来源本身是权威真值，不证明根因或修复，也不说明模型选择的比较常量是合法业务阈值。业务通过仍由用户配置的验收规则负责。

单个 JSON 输入不超过 4 MiB，一次核验累计输入不超过 16 MiB；数组不超过 100,000 项；每份报告不超过 32 条断言、每个 finding 不超过 8 条。数值精度和指数有边界。重复字段和运算复用读取与计算结果。

## 非结构化资料与旧接口

旧的引用式报告和纯文本证据仍可使用。没有结构化支持的 finding、以及旧格式摘要会标为“待核实解释”，原文引用仍保留，支持关系不会标为 deterministic。结构化 finding 的模型解释进入未核实说明，不能覆盖程序生成的事实文本。

关键词规则仅作为补充检查，已修复否定和不确定语句被当成肯定断言的情况；它不是通用语义推断器。自由文字的语义正确性没有得到自动证明。

模型提出的 expected/unexpected 标签会保留供参考；仅提供自然语言实验预期列表时，正式判读保持 `unknown`，不再把“有列表、有模型标签”当成已验证对应关系。

报告工具根据已收集证据是否适合 JSON 字段核验展示断言 Schema，纯文本任务保留较小 Schema。展示提示不参与信任判定；真正的断言始终回查原文。小窗口下的旧读取、检索与有限报告流程有离线回归覆盖。

公开 v2 Schema 增加 `EvidenceAssertion`，并为 Claim 增加可选断言字段；旧输入默认空列表。发布的 v1 Schema 快照保持不变。直接构造 `ReportService` 并发布结构化 Claim 的调用方需传入 artifact store；API、Worker 和原生发布器已接入，旧的无断言调用不要求新增参数。

## 检索范围与反证记忆

检索工作状态记录每次扫描的起点、游标、完成标记和扫描字节数，并随检查点恢复。后半段扫描完成不会覆盖前半段未覆盖的信息；扫描完成只适用于该次选择的已保存产物，不代表远端分页或整个运行已覆盖。

空数组的 `count eq 0` 只生成该证据数组的计数事实，不生成“整个运行没有失败”等全局断言。没有完整范围支持的自由文字仍是待核实解释。

工作笔记继续限制为 6,000 UTF-8 字节，优先保留假设账本引用的反证、错误结果和计划关联证据。所有笔记均须可追溯；优先保留并不证明模型标注的支持/反驳关系正确。关键笔记若仍因空间不足被淘汰，会记录遗漏，不能默认为已解决。恢复时去除已失效证据笔记，缓存命中也会检查引用证据是否仍有效。
