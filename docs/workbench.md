# TRACE 测试工作台

在项目根目录运行 `./scripts/start_workbench.ps1`，打开 `http://127.0.0.1:8080/`。界面由现有 FastAPI 同源服务提供，无需安装前端构建链，也不使用外部字体、脚本或 CDN。开发进程必须已安装 README 中的 Python 依赖。

当前工作台以统一主会话与监督面板为入口，集中呈现待关注事项、后台调查、来源事件和报告；每项调查可查看独立的计划、运行、预算与证据。界面布局、交互与验收范围见[监督工作台实现记录](supervisor-ui-implementation-2026-11-05.md)。使用 `Enter` 发送、`Shift+Enter` 换行。

浏览器按租户、项目、用户和会话保存未发送的草稿及最近访问的会话，刷新后恢复。身份设置和主题也保存在本机浏览器；JWT 登录 Token 仅保留在当前页面内存。共享电脑可清除站点数据来移除本机草稿。

## 本机模型配置

启动脚本与 `python -m game_test_agent` 默认加载 `data/local/workbench.env.json`。文件是环境变量名到字符串值的 JSON 映射，不执行脚本；已有进程环境变量优先。`start_workbench.ps1 -LocalConfig <路径>` 或 `GTA_LOCAL_CONFIG_FILE` 可选择其他私有配置文件。此文件位于 `.gitignore` 的 `data*/` 范围，不随源码发布。可从 `configs/workbench.env.example.json` 复制模板后填写。

模型通过 `GTA_MODEL`、`GTA_MODEL_API`、`OPENAI_API_KEY` 和可选的 `OPENAI_BASE_URL` 配置；兼容服务使用其实际支持的接口地址。工作台只显示端点和密钥是否配置，不提供密钥回读。

模型密钥与平台服务令牌是两种不同凭据。前者只用于模型接口，后者用于本机测试平台。配置更新后重启 Agent 服务生效；不把模型密钥写入浏览器存储、用户输入或对话报告。

## 测试平台只通过 MCP 接入

所有平台连接统一放在 `GTA_MCP_PROVIDERS_JSON` 或启动配置的 `mcp_providers` 中。Agent 不直接访问平台 HTTP API；用户访问 Agent 的 FastAPI 接口与 RabbitMQ 调查事件入口继续保留。

### 原生 MCP 工具调查

设置 `GTA_MCP_NATIVE_TOOLS=true`，Agent 使用 MCP 的 `tools/list` 发现工具，将原始名称、描述和输入 Schema 交给模型，再直接通过 `tools/call` 调用。工具结果按原文保存为证据，报告引用经过逐字核对。长返回可通过调查内部的证据检索读取原文；检索不转换平台数据。重复调用、上下文压缩和最后一轮报告生成均受预算控制。当前原生调查只授权读取，不由模型提交测试或修改环境。

```powershell
$env:GTA_MCP_NATIVE_TOOLS = 'true'
./scripts/start_workbench.ps1 -ProviderConfig configs/providers.native.example.json
```

配置只需要 MCP 地址、项目范围及工具权限，不需要选择平台契约。`allowed_tools` 是运维审核后的只读工具白名单；没有配置时只采用 MCP `readOnlyHint` 标记的工具。平台访问令牌由 MCP 服务管理；MCP 本身需要认证时使用 `token_env` 指定环境变量名，不把密钥值写进浏览器。

活动调查收到补充消息后，会在下一次模型决策边界采用新内容；若旧答案正在生成，会丢弃该答案再处理补充。消息下方的状态区分“等待下一步处理”和“已用于调查”。原生模式支持工作状态检查点和已核验报告草稿恢复。

原生调查由 LLM 通过内部工具 `agent_update_plan` 先制定 3–5 步初步计划，然后收集证据。计划与首次 MCP 读取可以在同一轮响应中按顺序执行，不额外预留一次模型请求。每步包含待验证问题、所需证据、完成条件和状态；阈值与实验预期应引用用户、用例或基线，缺失时保留为待确认问题。后端拒绝未保存有效计划就读取证据的请求，但计划本身不会扩大原有 MCP 权限或资源预算。

模型可按新证据和用户补充修订计划，必须提供当前版本号与调整原因。首次提交完整计划，后续仅提交按 `step_id` 标识的变化字段；未修改的步骤、问题与完成条件由后端保留，新增步骤必须提供完整字段，放弃的步骤标记跳过。后端在合并后重新校验完整计划。标记完成要求提供本次调查内可读的真实证据 ID 与结果说明；标记受阻或跳过要求说明原因。这些校验确认证据归属与结构，不验证模型推断的因果关系。重复无变化的更新被拒绝，反复修改计划不会延长预算或重置无进展检测。

保留的报告轮次关闭平台与证据读取，但仍允许更新计划和提交报告，避免收尾时无法记录已完成步骤或证据缺口。计划和报告均消耗原模型轮次预算；计划更新不计为平台读取，也不能恢复已经耗尽的读取额度。

对话显示初步计划和后续调整，调查面板显示当前步骤、完成条件、结果和可打开的证据。计划事件独立持久化，最近 20 次修订不受普通事件最近 100 条的限制；工作检查点和上下文压缩保留当前计划，重启从最新计划事件恢复。历史调查不补造计划，结束时未完成的步骤保留原状态。接口投影新增 `native_plan` 与 `native_plan_history`，原有结构化执行计划 `plan` 保持原语义。

执行面板展示累计输入/输出 Token、模型成功响应及复用读取次数。报告中的“已核对原文引用”说明引文与原文一致，不代表根因已确认。混沌调查可在额外约束中传入 `experiment_expectations.expected_effects` 与 `violation_conditions`；缺少明确预期时保持未知判读。详见 [工程审查](agent-review-2026-10-17.md)。

本机平台启动脚本默认启动 `8010/mcp`，可用 `-McpPort` 选择其他端口。MCP 服务内部访问本平台 API 属于工具实现；Agent 仅访问 MCP 入口。工作台连接指南只区分本机、远程地址预设，两者均使用同一套原生 MCP 调用流程。

平台原生混沌运行终态会持久化触发任务，经 RabbitMQ 发出调查事件；事件保留 `observation.native_reference`，供模型读取原始运行 ID。启动事件 Worker 后，运行失败可自动创建调查，报告经消息队列回传平台。重启补偿扫描负责修复终态提交与触发任务之间的中断窗口，并按结果哈希去重。

旧版结构化契约代码保留供已有配置兼容，但原生模式不加载平台适配器。参考模拟服务的测试结果不能充当真实游戏链路验收。

## 平台触发与用户主动调查

用户可在工作台提交目标、追加信息并查看报告。平台也可通过 RabbitMQ 发送失败事件，Agent 调查原始运行与证据，并经 Outbox 回传报告。原生模式的补测与故障注入由平台发起。事件桥通过来源、租户、项目和 scopes 校验授权；自动调查产生的子运行不递归触发自身。

本地模式使用 `GTA_ENABLE_LOCAL_EVENT_BRIDGE=true` 并配置 RabbitMQ 与 `GTA_EVENT_SOURCE_POLICIES_JSON`，与 API 进程共享调查所有者；Temporal 模式使用独立 Bridge 与 Worker。原始运行读取需要事件身份具备 `runs:read` 和 `evidence:read`，两种模式都从同一份 MCP 配置组装 Provider。

历史真实 HTTP 联调记录保存在 `data/local/auto-investigation-acceptance.md`，它记录当时的本地工作流，不是本次 MCP 接入的真实游戏验收。原生 MCP 的真实混沌链路验收记录另存于 `data/local/native-mcp-acceptance.md`。

## 对话和执行语义

- 新调查默认有 **120 分钟调查时间预算**和 **120 设备分钟预算**；前端「测试条件」统一以分钟填写时间，API 的 `max_wall_seconds` 仍以秒计（默认 7200）。多台设备的执行时间累计计入设备分钟。通过 `GTA_MAX_WALL_SECONDS`、`GTA_MAX_DEVICE_MINUTES` 可配置默认值，显式请求预算优先；已有调查和继续追问沿用其原预算，不会被静默放大。
- 调查总时间包含等待输入、排队和测试执行，重启不会重置截止时间。平台单次运行超时属于另一项执行约束：需要时在额外约束中设置 `action_constraints.timeout_seconds`，不能把总预算误当作某一次平台测试的超时。Lyra MCP 接受 1–21600 秒，未指定时保持平台适配器原有默认值。
- 本机启动会恢复未结束的调查，先核对原动作与原运行，提交中断时先按 action ID 对账，复用原幂等键；等待用户输入的调查保持等待。外部运行的状态查询按剩余时间与读取预算分配间隔，并为日志读取保留额度；事件通知可提前唤醒查询。到达总时限后，未确认结束的外部运行进入清理账本。
- 失败运行的首段文本日志会在权限和读取预算允许时自动进入下一轮上下文。失败实验的重复建议会收到结构化计划修正反馈，最多允许两次纠正，并继续受原轮数和资源预算限制；不会放宽计划、权限或证据校验。
- 工作台设置分别展示模型凭据配置状态与自动调查事件通道状态。事件通道暂时不可用时，API 和历史查询仍可用，后台重试连接；平台能力接口可达不代表游戏构建和执行环境就绪。
- 一条会话可以包含多轮关联调查，历史列表按最初调查归组。现有工作流负责规划、预算、幂等、运行轮询和证据校验，旧调查无需改写即可进入会话列表。会话按需分页加载更早的轮次。
- 运行中的补充信息写入持久命令与下一轮上下文。等待输入的本地调查会被唤醒，保留已有决策、剩余轮数、运行预算与原始总时限。
- 已结束任务的追问通过 `reopen` 创建关联调查，使用本轮问题作为目标，并沿用界面显示的条件、验收标准与新预算。服务端附带前轮目标、报告摘要与哈希，并标记为 `historical_reference`；前轮证据不会变成本轮采集结果。运行中的输入不修改正在执行的条件和预算。
- 会话发送要求当前调查 ID，并用持久幂等收据避免丢失响应后的重试重复创建任务。另一页面已推进会话时会返回冲突，刷新后再发送；修改名称、置顶和归档也使用独立版本控制。
- 归档隐藏会话并暂停继续发送，恢复后可以继续。它不取消运行，不删除调查、报告或证据；停止运行使用输入区的停止按钮。
- 页面通过携带原有认证 Header 的 `fetch` 接收 SSE 更新通知，再读取权威投影；连接中断自动重试，页面进入后台暂停连接。令牌不会拼入 URL。通知流为有界连接并支持游标重连；不是模型逐 token 流式输出，也不展示模型隐藏思考。
- 默认未启用模型，界面会标出规则模式。启用模型继续使用项目已有 `GTA_ENABLE_MODEL`、`GTA_MODEL` 和兼容端点配置；没有有效模型凭据时不能承诺自由对话或模型诊断。
- 报告先显示结论摘要、问题与建议，完整 Markdown 可展开或导出。文本证据分段追加读取，PNG/JPEG/WebP/GIF 可以预览，其他二进制产物可下载；下载先校验调查归属、作用域和 SHA-256。执行来源为 `real` 或 `simulated` 时显示不同标记。
- 本地工作流未处理的异常会保存失败状态与系统错误报告。停止调查会尝试取消尚未结束的外部动作；未确认结束的动作留在清理账本并在执行面板显示。

## 消息归属

任务栏默认开启“按内容识别任务”。普通补充留在当前任务；可写“继续「最初的任务目标短名称」：补充内容”转给明确指定的任务，或写“新任务：问题”创建独立调查。也可以使用任务编号。名称有歧义时才选择目标或返回编辑，不会提前投递。

跨任务补充沿用目标任务自己的条件；新任务使用界面显示的条件与预算。名称识别采用明确地址规则，尚不支持任意自由表达的模型语义判断；关闭开关后恢复当前任务定向发送。实现与上游源码对应关系见[第十一批记录](harness-phase11-implementation-2026-11-03.md)。

## Worker 退回补充

Worker 判断某条补充属于别的任务时，可以在探索阶段将它退回协调层；原任务继续，原文留在聊天记录中。用户原文有明确地址时自动转交，无法确定时显示在“退回消息”。可以查看原文后转交给当前会话内仍在进行的任务，或选择不再处理这条补充。关闭事项不停止原调查。

同一消息不能转回退回过它的任务，不能自动恢复已停止或过期的调查，也不继承原任务的代码权限。退回原因是 Worker 判断，不代表独立核实。需要新任务时，先通过已有入口明确创建，再转交原文。详见[第十二批实现](harness-phase12-implementation-2026-11-03.md)。

## API 与边界

`GET /v1/investigations` 提供租户/项目范围内的历史与游标；`GET /v1/workspace` 提供脱离凭据的运行配置；`POST /v1/providers/{id}/probe` 只发现已配置、当前项目可访问的能力，不执行测试；`GET /v1/providers/{id}/tests` 返回标准目录；`GET /v1/investigations/{id}/workspace` 汇总现有计划、决策、补充输入、运行、证据、事件与报告。所有数据接口使用原有 Header/JWT 鉴权；静态界面本身不含业务数据。

| 会话接口 | 用途 |
| --- | --- |
| `GET /v1/conversations` | 项目内的分组会话、搜索、归档过滤和分页 |
| `PATCH /v1/conversations/{id}` | 修改标题、置顶、归档；必须提供 `expected_revision` |
| `GET /v1/conversations/{id}/workspace` | 会话摘要与调查投影；支持 `before` 和 `limit` |
| `POST /v1/conversations/{id}/messages/route` | 记录消息归属，保留原文与幂等键；本身不投递或启动调查 |
| `POST /v1/conversations/{id}/messages` | 补充输入或追问；必须提供 `Idempotency-Key` 和 `expected_investigation_id` |
| `GET /v1/conversations/{id}/input-returns` | 待归属补充的短卡、数量和分页 |
| `GET /v1/conversations/{id}/input-returns/{return_id}` | 原文与已经退回过它的任务 |
| `POST /v1/conversations/{id}/input-returns/{return_id}/resolve` | 按修订转交原文或关闭待归属事项 |
| `GET /v1/conversations/{id}/stream` | 认证后的更新通知；支持 `after` 版本与最长 30 秒连接 |
| `GET /v1/investigations/{id}/evidence/{evidence_id}/download` | 经过归属与完整性校验的原始证据下载 |

SQLite 自动升级至 v21；MySQL 部署使用既有迁移工具应用至 `017_task_input_returns.sql`。消息归属复用既有收据表，Worker 退回状态使用新的 task_input_returns 表。会话展示元数据与消息收据使用独立表，不更改调查事件游标或证据账本。API 服务仍遵循既有单进程 Local / 生产 Temporal 部署边界。

连接与目录查询要求用户 `tests:read`，能力仍根据用户 scope 过滤。平台连接列表不返回 URL 或令牌，连接异常只返回受控错误码。测试、日志和报告通过 DOM 文本节点渲染，不执行平台提供的 HTML。生产仍遵循项目原有 JWT、Temporal、MySQL、S3 部署约束。

## 验证

`py -3 -m pytest -q` 运行后端回归。可选浏览器检查需要独立安装 Playwright 与 Chromium，在未配置 Provider 的隔离开发服务上运行 `py -3 scripts/workbench_browser_smoke.py`：只创建零运行预算的 QA 调查，验证连续追问、丢失响应后的幂等重试、历史恢复、搜索、元数据、归档、草稿、主题、报告导出、Token 存储和移动端抽屉，并输出截图。
