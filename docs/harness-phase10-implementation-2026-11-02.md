# 第十批：自动动作选择与召回执行保持一致

日期：2026-11-02。延续[渐进改造方案](super-agent-migration-plan-2026-11-02.md)。本批修复 Worker 内部自动候选选择与新增召回能力之间的接入断层，保留已有判断和排序规则。

## 问题与行为变化

第七、八批已经提供运行反馈和跨任务历史读取，但 agent_choose_next_action 仍只识别 inputs、input/ 和 evidence/ 引用。模型可以直接读历史，却无法通过已有选择器比较这些动作；注册崩溃、帧时间诊断也未接入候选校验。

缓存判断另有两处不一致：候选选择未统一空字符串查询，可能再次推荐已读结果；缓存的空搜索结果不随证据集合变化失效，后来新增相关证据时仍可能返回“未找到”。历史缓存失效的判断也没有完整复用于候选选择与结果日志恢复。

本批把这些能力接回原有自动调查流程，不增加人工选择“先查谁”的步骤。

| 场景 | 现在的处理 |
| --- | --- |
| 比较当前证据与已关联历史原文 | 两者均可作为合法候选，按原有缺口、竞争预测和成本排序 |
| 查阅反馈 | 只接受本调查已封批的投递游标；原始反馈仍是不可信通知 |
| 查找旧调查 | agent_find_history 可参与选择；发现卡片仍不授予原文读取权 |
| 使用注册诊断 | 校验 DiagnosticRequest、本调查输入和已有执行记录，不在选择时运行配方 |
| 空查询与省略查询 | 使用同一身份，已可复用结果不再被当作新动作 |
| 空搜索后新增证据 | 原缓存失效，允许重新选择和检索 |
| 选择后撤回历史关联 | 实际读取再次校验，拒绝读取；选择结果不是授权凭证 |
| 重启恢复旧读取日志 | 重新校验来源、版本和关联，失效材料不恢复为有效缓存或覆盖记录 |

## 共用读取状态

新增 workflows/native_read_state.py，将本地读取参数规范化、缓存身份与有效性检查提取为共用实现。原生执行器、候选选择器和已完成读取日志恢复共用它，避免各自复制一套规则。

证据搜索的缓存绑定本调查当前证据目录的 ID、SHA-256、来源修订和可读状态摘要，包括没有命中的搜索。证据集合增加、移除、修订或可读性变化都会使旧摘要失效。这里采用保守失效：即使新增证据不在某次搜索过滤范围内，也允许重新检索，不尝试猜测它是否相关。

单份本地证据读取绑定该证据的同类元数据；用户输入目录绑定完整输入身份与内容哈希；反馈目录沿用批次 generation；历史目录与原文沿用关联 generation、固定报告及证据 pin。历史发现每次获取新结果。外部 MCP 读取保留现有 30 秒缓存期限，不扩大远程调用权限。

搜索覆盖记录也保存目录摘要。在下一轮模型调用前，过期覆盖记录会被移除，不能把旧目录上的 complete 误当作新目录的搜索覆盖。该内部摘要不加入模型工作消息；有效摘录、查询范围、分页游标和原有约 2 KiB 覆盖记录预算继续保留。

旧检查点及调用日志没有状态摘要时，对需要摘要校验的结果保守失效，必要时重新读取并按原预算计数。没有预算时保留有限结论；不为兼容旧缓存补造当前有效证明。

## 引用校验与权限

RecallService、FeedbackStore 提供 validate_reference，供实际读取和候选校验复用。历史校验检查作用域、有效关联、固定报告完整性、报告引用的证据 pin 和可选内容哈希；反馈校验检查本调查的封批投递及可选哈希。历史证据 ID 中的斜杠仍按原读取链解析。

候选选择不打开原始 Artifact、不调用平台读取、不运行注册诊断或代码、不消费读取预算。为核验固定报告，历史服务仍会从台账加载报告模型；这不等于向 Worker 注入完整历史上下文。选择器保留原来的建议事件与短工作状态，不创建新的授权或历史关联。

控制器将本轮实际提供的工具名称传给候选选择器；没有展示的工具不能成为本轮推荐动作。普通调用本身仍执行原有 Schema、权限、预算和执行门禁。选择阶段只做可由元数据完成的检查，不预先打开文件验证 JSON Pointer 是否存在、UTF-8 字节边界或查询命中，实际读取仍可能返回可恢复错误。

历史内容继续使用 source_evidence_id，不会被导入当前证据账本。当前报告引用、结构化断言及反证核验保持原逻辑。Router 不接收 Worker 的完整读取历史。

## 改动与兼容

主要改动位于 native_read_state.py、native_reasoning.py、native_mcp.py、native_context.py、memory/recall.py 和 storage/feedback.py。

没有新增依赖、接口或数据库迁移。SQLite 仍为 20、MySQL 最低迁移仍为 016，NativeMemory 检查点版本仍为 5，继续读取版本 1–5。新增状态摘要位于检查点已有的缓存和覆盖记录字典中。没有修改冻结的 contracts/v1、contracts/v2。
